description: Unsupervised Learning Experiment Workflow
---

Phase 1: Data Acquisition & Dimensionality ProfilingAction: Ingest data and establish structural boundaries before applying any transformations.System Constraint Check: Do not load the entire raw dataset into main memory immediately if the file size exceeds 50% of available RAM. Stream the data to profile it.Dimensional Profiling: Calculate and log the total observations ($N$) and total dimensions/features ($p$).Sparsity Calculation: Compute the global sparsity ratio. Use this metric to conditionally branch the architecture in Phase 2 (e.g., if sparsity > 90%, force sparse matrix representation; otherwise, use dense arrays).Phase 2: Geometric Transformation (Preprocessing)Action: Map domain-specific semantic concepts (e.g., words, categories, timestamps) into a formal, strictly numerical coordinate system.Imputation & Integrity: Drop or impute missing values to guarantee a complete matrix. The algorithmic engine must never handle nulls.Vocabulary Definition: Discretize, normalize, or encode variables based on the required geometric space.For discrete/combinatorial algorithms: Use maximum-entropy splits (e.g., median cuts) to ensure dummy variables have uniform mass.For continuous/distance-based algorithms: Apply standard scaling or vector embeddings.Memory Architecture: Instantiate the data structure based on the Phase 1 sparsity profile. Use structures like Compressed Sparse Row (CSR) for high-dimensional discrete data to prevent Out-Of-Memory (OOM) failures.Phase 3: The Algorithmic Engine (Strategy Pattern)Action: Execute the core mathematical optimization or combinatorial search.Interface Design: The pipeline must utilize the Strategy design pattern. The preprocessing module (Phase 2) and the evaluation module (Phase 4) must not care which algorithm is running.Engine Implementation:Baseline Engine: Implement a naive or brute-force algorithm first to establish a correctness baseline. Explicitly log time complexity and memory bottlenecks.Optimized Engine: Implement the mathematically optimized algorithm (e.g., tree-based compression, gradient optimizations) to bypass the baseline bottlenecks.Resource Sweeping: Implement a hyperparameter sweep starting from the safest, most restrictive bounds (e.g., highest thresholds, lowest learning rates) and systematically loosen them until the hardware compute/memory ceiling is reached.Phase 4: Pattern Extraction & Metric CalculationAction: Translate undirected or raw mathematical outputs (e.g., weights, itemsets, eigenvalues) into structured, directional relationships.In-Memory Computation: This phase must be purely CPU-bound. Do not query the original database or hard drive. Use the cached outputs from Phase 3 to compute secondary metrics (e.g., Confidence, Lift, Feature Importance, p-values).Metric Generation: Assign rigorous statistical bounds or heuristic scores to every discovered pattern to prepare them for filtering.Phase 5: Evaluation & Semantic Post-ProcessingAction: Filter mathematical noise and translate the geometric outputs back into human-readable, domain-specific logic.Threshold Filtering: Apply user-defined constraints (e.g., minimum confidence, maximum error, significance level) to cull the raw outputs.Redundancy Pruning: Implement an automated filter to drop mathematically redundant outputs where adding complexity yields no significant information gain.Semantic Restoration: Reverse the mapping performed in Phase 2. Translate the winning matrix indices, vectors, or mathematical rules back into the original categorical strings or human concepts.Final Output: Format the final results into a structured log, dashboard, or secondary database table suitable for downstream consumption.Architectural Invariants (Rules the Agent Must Not Break)Decoupling Principle: The algorithm in Phase 3 must remain blind. It must only see numbers, matrices, and distances. It must never contain hardcoded domain logic or semantic strings.Memory Protection: The agent must actively anticipate combinatorial explosions or dense matrix bloat. It must protect the system memory by pruning early and using appropriate data structures.Measurable Output: Every output passed from Phase 5 must be bounded by a quantitative metric proving its statistical relevance.
