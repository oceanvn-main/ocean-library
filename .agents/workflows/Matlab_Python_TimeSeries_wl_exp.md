# Workflow: MATLAB-Python Time Series Experiment (Matlab_Python_TimeSeries_wl_exp)

Use this workflow to design and execute a comprehensive Time Series Analysis experiment that leverages the strengths of both MATLAB (for deep algorithmic understanding, physical modeling, and classical econometrics) and Python (for scalable MLOps, modern automated forecasting frameworks, and deep learning sequence models).

Trigger this workflow manually or when building new `exp_*_timeseries.m` and their Python counterparts.

---

## 🏗️ Phase 1: Conceptual Foundation & Algorithm Implementation (MATLAB)

*Objective: Use MATLAB's robust mathematical environment to load, clean, analyze, and build foundational classical models. This phase emphasizes rigorous data preparation and statistical testing.*

### Step 1.1: Data Ingestion & Native Structures (`timetable`)
- **Action**: Load raw time series data (CSV, MAT) and immediately convert it to a `timetable`.
- **Purpose**: Ensures robust handling of timestamps, timezone alignment, and irregular sampling.
- **Functions**: `readtimetable`, `retime`, `synchronize`.
  ```matlab
  % Load and regularize timetable to a daily frequency
  TT = readtimetable('data.csv');
  TT_regular = retime(TT, 'daily', 'linear');
  ```

### Step 1.2: Exploratory Data Analysis & Feature Extraction
- **Action**: Decompose the signal to identify trend, seasonality, and residual noise.
- **Purpose**: Understand stationarity and basic temporal patterns.
- **Functions**: `autocorr` (ACF), `parcorr` (PACF), `adftest` (Augmented Dickey-Fuller).
  ```matlab
  % Test for stationarity and plot Autocorrelation
  [h, pValue] = adftest(TT_regular.Value);
  autocorr(TT_regular.Value);
  ```
- **Constraint**: Ensure any data imputation (`fillmissing`) or smoothing (`smoothdata`) uses only information strictly from the past (causal filters) to prevent data leakage.

### Step 1.3: Classical Modeling & Algorithm Implementation
- **Action**: Implement baseline mathematical models to establish a performance floor.
- **Purpose**: Understand the mathematical mechanism using explicit computation, fitting an ARIMA, SARIMA, or State-Space model.
- **Functions**: `arima`, `estimate`, `forecast`.
  ```matlab
  % Specify and estimate an ARIMA(1,1,1) model
  mdl = arima(1, 1, 1);
  EstMdl = estimate(mdl, TT_train.Value);
  [Y, YMSE] = forecast(EstMdl, 10, 'Y0', TT_train.Value);
  ```
- **Rule**: Follow the strict Train/Test split described in the official Data Science Pipeline.

### Step 1.4: Advanced Signal Processing & Analysis (Optional)
- **Action**: Transform data into the frequency or time-frequency domain.
- **Purpose**: Identify hidden periodicities or non-stationary frequency components.
- **Functions**: `pwelch` (spectral density), `cwt` (Continuous Wavelet Transform).
- **Visualization**: Plot strictly using `OceanViz.Core`.

### Step 1.5: Data Export for Python Pipeline
- **Action**: Export the cleaned, normalized datasets (`X_train`, `X_test`, `y_train`, `y_test`) to Parquet format.
- **Purpose**: Ensure Python receives identical, immutable, and typed dataframes.
  ```matlab
  parquetwrite('lake/processed/train.parquet', trainTable);
  ```

## 🐍 Phase 2: Modern Pipeline & MLOps Integration (Python)

*Objective: Scale the foundational concepts using modern Python data science ecosystems, focusing on automated forecasting, deep learning architectures, and production pipelines.*

### Step 2.1: Data Ingestion and Pipeline Setup
- **Action**: Read the Parquet files generated by MATLAB into pandas.
- **Purpose**: Establish the Python data pipeline using `pandas` DatetimeIndex.
  ```python
  import pandas as pd
  df_train = pd.read_parquet('lake/processed/train.parquet')
  df_train.set_index('Timestamp', inplace=True)
  ```

### Step 2.2: Automated Forecasting & Machine Learning
- **Action**: Apply modern forecasting frameworks that abstract the training loops.
- **Purpose**: Utilize models that natively handle multivariate series and exogenous variables (e.g., LightGBM, XGBoost via `sktime` or `Darts`).
  ```python
  from darts import TimeSeries
  from darts.models import LightGBMModel
  
  series_train = TimeSeries.from_dataframe(df_train, value_cols='Value')
  model = LightGBMModel(lags=12)
  model.fit(series_train)
  forecast = model.predict(n=10)
  ```

### Step 2.3: Deep Learning Sequence Models (Optional)
- **Action**: Implement architectures designed for complex, non-linear temporal dependencies.
- **Purpose**: Move beyond classical statistics to models like LSTMs, GRUs, or Transformers (PatchTST, TFT).
- **Tools**: Use `neuralforecast` or raw `PyTorch`.
  ```python
  from neuralforecast.models import LSTM
  from neuralforecast import NeuralForecast
  
  # Configure and fit LSTM model
  models = [LSTM(h=10, max_steps=500)]
  nf = NeuralForecast(models=models, freq='D')
  nf.fit(df=df_train)
  ```

### Step 2.4: Evaluation and Productionization
- **Action**: Evaluate model performance against the MATLAB baseline.
- **Purpose**: Determine if the complexity of the Python ML/DL models provides significant lift over classical MATLAB models.
- **Metrics**: Compute MAE, RMSE, and MAPE.
- **Artifacts**: Serialize models (e.g., via `joblib` or `MLflow`) for simulated production deployment.

## ⚖️ General Rules for this Workflow

1. **Explicit Computation**: In MATLAB, derive outputs explicitly without hidden heuristics. 
2. **Reproducibility**: Fix random seeds (`rng` in MATLAB, `np.random.seed` in Python) in both environments to ensure determinism.
3. **No Latex in Explanations**: Use plain text Unicode for mathematical variables (e.g., y_t, delta, mu, sigma) when writing comments or documenting equations in scripts.
4. **Data Isolation**: Never encode expected answers or use test data in the training phase across either environment.
